This run fires at :55 past 13, 16, 19 and 23 UTC on Thu, Fri, Sat, Sun and Mon (Pacific: 5:55 AM for international games, 8:55 AM, 11:55 AM and 3:55 PM), about 65-95 minutes before each kickoff window. For every player in those legs (and the QBs and key skill players of both teams in each window game), check official inactives and last-minute news: ESPN game summaries and injuries (site.api.espn.com), the nflverse injury report (`https://github.com/nflverse/nflverse-data/releases/download/injuries/injuries_2026.csv`, final designations), team and beat-writer reports, and WebSearch for "<team> inactives". ## 3. Closing prices (always, for every window game)
Fetch odds for each window game: `GET https://homies-sportsbook.vercel.app/api/odds?scope=event&id=<game id>&group=<group>` for each group that holds a published leg (lines, halves, passing, rushing, receiving, defense, td; board markets via `?scope=board`). - On each window leg set `cl` = DK's current price for the exact same market, outcome, player and line (omit if no longer offered), and `clp` = the closing no-vig probability of that outcome: de-vig Pinnacle when it has both sides, otherwise take the median de-vigged probability across the `cs` books that price both sides (for Over-only alt ladders, the median implied probability scaled by that book's vig on the main line). Round `clp` to 3 decimals.
- Save everything you fetched for each window game to `odds/close/<game id>.json.gz` (gzip JSON: `{"at": "<UTC ISO>", "groups": {<group>: <response game object with mk, px, cs>}}`; if the file exists from an earlier run, overwrite it with the newer prices). - Budget: about 250 Odds API credits this run (each event-group call costs about 1 credit per market returned; log `meta.remaining`). Published legs first, candidates second. If `meta.remaining` drops below 3000, say so at the top of the report so the owner knows to add credits.

## 4. Swap legs that are dead
A leg must be swapped if its player is inactive or out, or if news makes it very likely to lose (a QB change for a passing leg, a starter ruled out that the leg depended on, a role clearly cut, a forecast that turned badly for a passing, receiving or kicking leg). Swap only when NONE of that parlay's legs has kicked off yet; if a leg in the parlay already started, leave it and note it in the report.
For each swap: pick the best replacement leg from a game that hasn't started (prefer the same game and position group, keep the parlay's correlation sensible), with fair probability >= 0.65. Price it like the main routine: the no-vig market probability from Pinnacle, else the `cs` consensus median, shaded by the latest news by no more than 6 points; DK's price must be at or better than the consensus, and keep the parlay's EV at least as good as it was. Prefer legs in the -250 to -650 range; a defense or kicker leg only if it is clearly among the best on the board. Copy the new leg exactly from a response fetched this run (ev, home, away, t, mk, n, d, p, o) and add `fair`, `cl` (= its current price), `clp`, and `swap`: a short string like "Replaced Player X Over 39.5 rec yds (inactive) 8:55 PT". Respect the app rules: no two legs in one parlay share game + market family + player/team (both sides, Over/Under, main and alt line on the same stat); no near-duplicates such as a team's moneyline with its own spread or a QB's pass yards with the same QB's pass+rush yards; avoid player_pass_longest_completion. Recompute that parlay's `prob` and `ev` (payout = product of decimals, each same-game group's profit x 0.8) and add one sentence about the swap to its `why`. Never change a parlay's `stake`.
